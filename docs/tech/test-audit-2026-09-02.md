# The test audit, 2026-09-02

Landed the same day as phases 1 to 4 and phase 7, over the suite those phases left behind. The rebuild moved 1,451 tests into six package directories and then grew them to 1,643, and growth of that shape carries three things: a test that patches an internal because the seam it wanted was not there, two tests that assert the same behaviour because the second author did not find the first, and a name that says which function ran rather than what it does. The audit read every test file in `tests/` with those three in view, applied what survived a skeptic pass, and left the rest written down here. The goal was fewer, sharper tests, not more of them: one new test was added in each area only where a correctness fix had nothing pinning it.

The suite is 1,625 tests, green, `ruff check .` clean and `lint-imports` at three contracts kept. Nothing that came out took a behaviour with it: every deletion is either a second assertion of a claim another test still makes, or a body folded into a parametrize that keeps every case as its own row and id.

The `agent` count does not move because its five deletions were bodies folded into parametrize rows: 98 test functions became 96 while the collected ids stayed at 102. The `gates` row shows no mock removed because a skeptic pass confirmed all five of its stand-ins as keepers, every one a public parameter of the function under test (`validate_verifier`'s and `loophole_probe`'s `run_probe`, `policy_gate`'s evaluator). The cross-package row is the integration pass: seven tests moved to the package whose module they test, and the one deletion is a wall-clock assertion in `tests/test_e2e.py` that passed on a machine of any speed whatever the code did.

The mocks that came out were of one kind: a stand-in for something the repository already ships. `tests/runner/test_verdict.py` and `test_regrade.py` each carried a hand-rolled `simple_canon`, so both now pass `kullback.runner.canon.canon_value`, which is `verdict()`'s own default; `test_canon.py`'s `FakeJudgeResult` became the real `JudgeResult`; `tests/builder/test_pipeline.py`'s `FakeCeiling` became `kullback.runner.budget.Ceiling` charged for real; `tests/builder/test_cluster.py`'s two `class T` stubs became real `Trace` records; `tests/builder/test_verifier.py`'s `LowerCanon` became the shipped `CanonRules`; `tests/test_report.py`'s `SimpleNamespace` router became a real `RouteResult`. Two removals needed a seam rather than a substitution: `compile_env._confinement_block` gained `denied=` and `allowed=` parameters so a test could vary the deny list without patching the module constant, and nine provider tests that only read a request body now call `build_body` directly instead of standing up a mock transport. Where a patch survived, the reason is now written at the patch.

The duplicates were mostly parametrize rows that had been written as separate functions: five `cache_key` tests in `test_regrade.py`, four sub-answer tests in `test_judge.py`, three `check_context_cap` tests and three cost tests in `test_budget.py`, three `same_path` tests in `test_verdict.py`, the leak trio in `test_verifier_suite.py`, four one-line both-scorers tests in `test_verifier_runner_agreement.py`. Each fold keeps every case as a row with an id and keeps the D-numbered docstring, so what a reader loses is the copied setup and nothing else. A second group was a test whose whole body was a subset of another's: `test_ceiling_charges_the_call_before_it_stops`, `test_runner_version_moves_when_a_runner_file_changes`, `test_a_hard_rule_is_asked_about_a_tool_the_seed_runs_never_used`. In each of those the survivor gained the one assertion the deleted test owned before the deletion.

Weak tests were fixed rather than deleted where the claim was worth keeping. `test_a_comparison_with_no_cache_key_records_no_use` asserted an unrelated empty queue and now asserts the uses file is not written, with a positive control; `test_budget_does_not_import_the_builder` was a substring search over the module's text and now walks `import_closure`; `test_scorecard_is_json_serializable` only asserted that `json.dumps` did not raise and now asserts the round trip; `test_the_scorecard_gate_is_never_green_over_nothing` read `.get('pass', .get('passed'))` and was vacuous when neither key existed; `test_two_judges_without_a_workdir_writes_nothing` asserted on the fixture rather than on the code. About thirty names were rewritten into sentences, and the ones that resisted a sentence usually turned out to be two tests: `test_registry_holds_by_name_and_renders_schemas` was split rather than renamed.

## The two high findings

The first is a security finding, and it was the same defect at three `exec` sites. Model-written code, a Verifier atom, a policy predicate or a hard rule, ran with the process-wide builtins allowlist handed straight in, and the `dict(env)` around it is shallow. An atom whose predicate popped `len` out of that mapping therefore blinded every atom and every predicate that ran after it in the same process, including the ones deciding a later Verdict. Nothing in the confinement gate stopped it, because the gate refused reaching for a module and not naming the mapping. The fix is a fresh copy at each site, `dict(SAFE_BUILTINS)` in `runner/atom_context.py`, `dict(SAFE_PREDICATE_BUILTINS)` in `gates/artifacts.py`, `dict(SAFE_BUILTINS)` in `gates/verifier_suite.py`, and `"__builtins__"` added to `runner/confinement.DENIED_NAMES` so the name cannot be written at all. Each site has one test that asserts both halves, that the source is refused and that the next predicate still has its allowlist, so removing either half turns a test red. One consequence is worth budgeting for: `compile_env._confinement_block` renders the tool-body prompt from the confinement constants by design, so the new name is in the prompt, seven of 174 memoized tool-body requests changed text, and the next live build pays for seven fresh calls once. No ruling and no stored reply changed.

The second is in the TUI. `Screen._status` read `g["passed"]` off each ruling while `GateResult.as_dict` writes `pass`, so the status line reported gates by a key that was never there. It now reads `g.get("pass", g.get("passed"))`, the test builds its `state.json` through `as_dict(GateResult(...))` rather than by hand, and reverting the read turns the test red. The hand-built fixture is why the bug survived: the test wrote the key the code was looking for.

## What the checks say

`uv run pytest -q -o addopts='' -p no:cacheprovider` is 1,625 passed in about 34 seconds, `uv run pytest --co -o addopts=''` collects 1,625, `uv run ruff check .` passes and `uv run lint-imports` keeps three contracts. The integration pass also snapshotted a build before and after and compared every file by content hash: sixteen files differ and all sixteen are on the permitted list, `runner_version.json` (whose job is to move when those packages change), `budget.json` (identical once `wall_ms` is dropped), and fourteen sandbox `out.json` files that differ only in a nonce. Fifteen files were renamed with byte-identical contents, eight stage cache keys carrying a moved `code_version` and the seven memo keys the confinement prompt moved. No gate ruling, no replay and no compiled body changed.

## What remains open

Three mock sites stayed, each now carrying its reason at the patch. `tests/test_cli.py`'s `fake_modules` survives for `build`, `run` and the three verdict tests whose kwargs (`write_tools`, `flagged_tools`, the entity schema) are not carried on the stored Verdict, so there is nothing on disk to assert them against; the other five verdict tests moved onto the real Runner. `tests/test_tui.py` replaces `builder_agent.run_builder` for one test, the only claim the `runner=` seam cannot make, which is which callable the Screen reaches for when nothing is injected. `tests/builder/test_memory.py`'s `node_parses` counts parses by wrapping the real parser and delegating to it, because a count is the only way D65's laziness is observable. The first of those closes when a Verdict records the tools and schema it was scored with; the second when the Screen's default is a value rather than a lookup.

Eight test names are still shorter than a sentence, and each is a name whose test does one thing: `test_no_retry_on_a_plain_400`, `test_tau2_fixture_ingests`, `test_cycle_is_refused`, `test_oracle_run_passes`, `test_empty_run_fails`, `test_forbidden_write_fails`, `test_suggestion_never_decides`, and `test_model` in `tests/conftest.py`, which is a fixture and not a test. They were left because renaming them adds words without adding a claim.

Four findings were confirmed and deliberately not applied. `gates/artifacts.py:242` should record `referenced_ids` in the `build_environment` gate's metrics, which moves `gates.json` and so waits for a pass allowed to move a build artifact. `gates/artifacts.py:131-186` is a second implementation of the five compile-tools rulings that `gates/tool_runs.py` now owns; the choice is written down in `phase-4-builder-extension.md` and the deletion is a phase-4 item because it moves the registry's spec and ruling counts. `verifier_suite.loophole_probe`'s `run_probe` parameter should become the probe Run itself, a signature tidy the gate's behaviour does not depend on. `verifier_suite.check_run` recomputes a run's effects, asked fields and said text per atom rather than once, which is invisible at today's Run sizes and worth doing when an atom count makes the scan measurable.

One finding needs a decision rather than a patch. `runner/atom_context.py:239` hands `start_state` and `end_state` to a predicate as the live dicts, so `end_state["orders"].clear()` in one atom changes what the next atom reads. Deep-copying costs per atom and would make `gates/confinement.py`'s predicate gate refuse a different set of predicates, so it was excluded from the behaviour-preserving claim rather than slipped in.

The rest are smaller and unforced: the `floor_blocked` counter the agent core does not keep (D131 instrumentation), a `loaded_tools` property in `context_tools.py`, the unreachable `pinned_tools.add("note")` under the files arm, the flat re-export list in `gates/__init__.py`, having `cli.py` construct the `BuildPlan` so `build.build()` and `run_builder()` can drop their duplicated eighteen-field signatures, and a shared fixture over the real `SimulatedUser` for `tests/builder` so `test_loop.py` stops hand-building the `user_turn` payload keys that `loop._user_payload` reads. The audit also listed gaps where no test exists at all, mostly refusal rules in `context_tools.py`; those ask for new tests and were left to whoever adds the behaviour they guard.
