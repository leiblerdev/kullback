# Trace source eligibility

Written 2026-09-24, in answer to "explore all other datasets and their eligibility as well." Kullback rebuilds an Environment from recorded agent traces: it mines the tool calls, derives a Starting state, rebuilds each tool body, then replays every recorded call and checks our answer against the recorded one (fidelity), and a trust gate needs a second recorded Run per Task as held-out evidence. This file scores every dataset found against that need, reusing docs/benchmark-landscape.md's facts (2026-08-29 survey) rather than redoing them, and adding what that survey did not cover: named trajectory releases for WebArena, OSWorld, AndroidWorld, SWE-bench and SWE-Gym, MCP-Universe, plus a fresh Hugging Face and GitHub sweep.

A parallel Worker is writing docs/trace-sources/exgentic-agent-llm-traces-v2.md, itbench-trajectories.md, terminalbench-trajectories.md, toolathlon.md, appworld.md, real-world-candidates.md and README.md. Their datasets are still scored here, in the shared table below, but their files are not written by this pass. `real-world-candidates.md` is a grouping file for several small real-world corpora, not one dataset, so it has no table row of its own.

## Eligibility test

Score every dataset on each, yes / partly / no, with the reason:

- **E1.** Tool calls with arguments AND the returned results recorded (not just the model's text).
- **E2.** A reference environment we can run or query: offline package, container, or live public API.
- **E3.** Several recorded Runs per Task (at least two), for the held-out check.
- **E4.** Licence allows our use and publishing a derived Environment (quote it; "none stated" is a no for publishing).
- **E5.** Provenance: real people or real systems (best), human-written tasks with model runs, or fully model-made.
- **E6.** Structured state we could rebuild (tables, records), not only free text or pixels.

Verdict per dataset: eligible now / eligible with work (say what work) / not eligible (say why).

A verdict of "eligible with work" never means "we would build our own traces by running an unfamiliar environment ourselves", that is a different project (self-generation under D60) and is called out separately where it applies. It means published traces exist but need an access, format, or licence step before Kullback can ingest them.

## Best candidates

At most five, ranked by how directly they fit Kullback's shape and how little work is needed to find out:

1. **AgentLogs** (risenlab/agentlogs). Real production Copilot cloud-agent activity on real public GitHub repos, CC BY 4.0, 307k tasks and 64M log entries with tool call arguments (`toolName`, `command`, `filePath`, `diff`) paired with an `output` field. First step: `snapshot_download` the `agent_session_logs` and `agent_tasks` configs and measure what fraction of entries have a non-null `output`.
2. **SWE-bench trajectories (Nebius)**. 80,036 published trajectories with tool calls, results and test execution logs, CC-BY-4.0, and SWE-bench's own per-instance Docker images already exist as the standard way to replay them. First step: pull a slice of `nebius/SWE-agent-trajectories` and confirm several trajectories share the same `instance_id`.
3. **MCPMark**. A published trajectory log with multiple runs per task/model pair, MIT licence, and real live backends behind it (Notion, GitHub, Postgres, Playwright). First step: download a few `run-1`/`run-2` trajectory folders for one task and confirm `messages.json` carries both the call arguments and the tool's result, since the HF dataset viewer currently errors on this file.
4. **tau-bench (original)**. Same reference-database shape we already build from, MIT, `historical_trajectories/` published, and a Pass^k evaluation that implies several trials per task. First step: clone the repo and diff its trajectory schema against the tau2 export our ingest already reads.
5. **AgentTrove**. 1.7M rows, Apache 2.0, already the subject of internal analysis (docs/decision-log.md, docs/learnings.md, docs/papers.md) and the founder's own stated interest. First step: fix the intake gap already named in docs/learnings.md section 3 (refuse an empty-world build) before treating any AgentTrove sample as a Reference.
