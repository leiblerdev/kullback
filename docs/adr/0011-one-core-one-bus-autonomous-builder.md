# ADR-0011: One core, one bus, an autonomous Builder with tools

Status: accepted 2026-09-22. Implementation pending at decision time; the streams that build it are numbered in `docs/architecture.md` and every learning it carries or drops has a row in `docs/overhaul/learnings-ledger.md`.

Context: two live rounds on 2026-09-22 (airline rounds 6 and 7, retail round 2, on openai/gpt-5.6-luna over the integrated code d90d929) moved nothing. Airline fidelity was 0.6303 in both rounds, 75 of 119 Tasks replayed in both, and the kept body's hash (176ea811) was identical before round 6 and after round 7, across six recompile attempts and six reverts. Seventy-two percent of a round's spend went to stages that cannot change a body (rerolls 34 percent, policy 26, reference judge 9, probes 3), and the two findings that named the fidelity failure did not surface until round 7, after round 6's spend was gone. Trusted is zero everywhere on the next round: every derived Verifier carries a policy rule compiled as a judge must-hold hard atom (airline 54 of 54, retail 194 of 194, telecom 26 of 26), and since D255 the code-only scorer fails a Run on any judge atom, so the 46 trusted the baseline showed is a count left on disk by an earlier build (H1). Underneath H1 the reading found six more root causes: a thinner sighting of a row taken as a new version of it, so 502 subset rows are pinned and one gate ties for sixteen recompiles (H2); only the assistant's calls counted as sightings, so 42 of 51 calls in one Task are dropped before any reader runs and 76 telecom Tasks fail before a body of theirs writes anything (H3); a lesson catalogue that cannot state the relation that is wrong, so a Builder is told the sign of a formula and never its multiplier (H4); starting rows pinned from masked readings and renders the Builder ignores (H5); a loop that spends where nothing can move (H6); and a corpus that is not buildable but that no gate refuses (H7). The full analysis is `.claude/reports/harness-failure-analysis-2026-09-22.md`; its lessons are `docs/learnings.md` section 7. The cause under the causes is structural: the Builder was a scheduler over a declared stage graph (`kullback/builder/pipeline.py`, `build.py`). It could call stage verbs, it had no tool that could read a body, a recorded call, a row or a diff, no tool that could write one, and its only hand was a fresh one-shot writer with no memory of what the last attempt tried.

Decision, in seven parts, each with the alternative that lost.

1. The Builder edits its Environment with file tools over a root, not with typed write verbs. It gets the base tools (read, write, edit, bash, grep, find, ls, web_search) rooted at its own `env/`. Considered: a typed write tool per artifact (`write_body`, `write_row`), which is easier to validate and was how the verb tools already worked; it lost because a typed tool can only express the edits someone anticipated, and the round that failed is the one where the Builder had to do something nobody listed.

2. Boundaries have two levels, cannot and should not. Cannot is a tool that is not registered for that extension: the Simulated user has no file tools at all, the Examiner has no write and no bash. Should not is stated in the prompt. The shell is the one tool that is many tools, so bash takes a command allowlist and a cwd, checked once inside the tool, and refuses a command off the list, an absolute path or a parent step. Considered: a path resolver in the agent core that every tool call passes through; it lost because it puts application knowledge in a core that is meant to know nothing about the application, and because it makes every extension pay for a check that only the shell needs.

3. One loop. The candidate inside a Run is an agent on the core with only the Environment's tools registered, and the Simulated user is an agent on the core. Considered: keeping the Runner's own loop beside the agent core, which is what exists today and is what the version hash was invented to freeze; it lost because two loops mean two definitions of a turn, of a tool result and of a stop, and the harness grades Candidates against a loop it does not use itself.

4. The Builder calls examine. It ingests, derives the world, reads and edits, runs replay and reroll through the runner tool, calls examine when it judges the Environment ready, acts on the findings, and stops when every Task is trusted or refused with a reason, when the spend hook says the allowance is gone, or when it states why it cannot go further. Considered: the CLI alternating the two agents, a round of four beats ending at gates (D126, D128); it lost because the schedule decided when the Examiner looked, and it looked one round late, which is exactly what the two rounds of 2026-09-22 paid for.

5. Carve, never rewrite. Pure, measured modules are moved verbatim in one commit and wrapped as tools in the next: mine, readers, cluster, canon and the starting state together become derive_world, the sandbox and the body gates stay gates, the runner keeps its route, its world and its Verdict, the user keeps its rules and guards, the Examiner keeps its Verifier suite. Considered: a rewrite on the new shape, which would have been cleaner to read; it lost because those modules carry two hundred measured decisions and a rewrite loses them silently, which is why the ledger exists and why the move and the change land in separate commits.

6. The Builder never writes world rows. Rows are derived by code from the recordings (derive_world). The Builder may grow a table with synthetic rows, never in a trusted Task, and may file a data finding. Considered: letting the Builder edit rows directly, which is the obvious use of a write tool and would have closed H2 and H5 by hand; it lost because a row the Builder wrote is a row it can make its own body agree with, and fidelity would then measure the Builder against itself.

7. Gates are bound to paths, and one hook appends the ruling to the tool result with the rows that still differ. A write under `env/tools/` runs the body gates, a write under `exam/verifiers/` runs the Verifier gates. Considered: gates called by the stage that produced the artifact, which is how they ran; it lost with the stages, and binding to the path is what makes a gate unskippable now that the write is a file write.

Why, in one line: the Builder was given findings it could not act on, through a hand that could not hold them, on a schedule that delivered them too late, so the fix is a hand (tools), dense feedback (rows, not counts) and no schedule (autonomy).

What of ADR-0007 stands: no agent writes the gates or the runner, and that is enforced by registration and by the gate on the path rather than by a raising hook alone. The Examiner still never reads a tool body and never writes the Environment; the Builder still never writes a Verifier, a probe, a gate or the runner. The generator-grader separation is unchanged. What is reversed: ADR-0007's reading that the Builder repairs the Environment through verbs the harness owns. The Builder edits its own Environment files directly. ADR-0007's messaging between the two agents by queues is also replaced, by one append-only sequence-numbered bus per workdir that every harness and every tool publishes to and every consumer subscribes to; transcripts stay per agent, because they are context and not events.

Consequences. What becomes possible: a Builder that can read the diff it is meant to fix and edit the body in front of it, keeping in its own transcript what it has already tried, which is what neither the one-shot writer nor keep-by-beating could do; a finding that carries the rows that differ per call instead of a count and a gate word; feedback inside the same session rather than the next round; one loop to improve instead of three; and one bus, so the tui, the journal, the feed, the report and the Examiner's finding collector are subscribers rather than five bookkeepers.

What is lost. Content-addressed caching of stages beyond the first pass: without a declared graph there is nothing to key a stage cache on, so ingest and derive_world cache their own first pass and everything after it is paid for again. The Examiner's independence in time: it now looks when the Builder asks, so a Builder that never asks is a Builder that never gets examined, and the stop rule and the spend hook are what make that visible. The frozen runner's independence from the core loop: with one loop, a change in the core can change a Verdict, which the freeze was meant to prevent; a version hash of the runner's own code plus the core loop it ran on is stored beside every Verdict, so a Verdict always names the code that produced it and two Verdicts are only comparable when the hash matches. Also gone, with their rows in the ledger: the round and its journal, the stage scheduler, the verb tools, the context manager's four tools (compaction now mirrors tau, automatic at 40 percent, manual on request, the older prefix summarised and recent turns kept verbatim), and the round tables and snapshots as code, which become bus subscribers if they are kept.

Open founder decisions, carried over unchanged by this ADR. Atom classes under D255: whether a hard policy rule with a structured target becomes a code atom and one without stays diagnostic, or judge atoms stay diagnostic everywhere, or nothing is trusted until policy rules compile. AgentTrove: pursue the registry and container pieces now, or park it until the three corpora are at fidelity. The five retail Tasks that reproduce a bug in the source recording: count them apart or reproduce them. The re-freeze of `runner_version` on the integrated runner. None of these is decided here, and none of them is blocked by this ADR.

See `docs/overhaul/learnings-ledger.md` for where each earlier decision lands, `docs/learnings.md` section 7 for what the live rounds taught, and decision log D120 to D128, D135, D141, D211, D255 and D266 for the entries this ADR supersedes or carries.
