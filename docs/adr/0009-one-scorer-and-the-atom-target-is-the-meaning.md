# ADR-0009: A Verifier has one scorer, the structured atom target is an atom's only meaning, and text-related rewards are grounded in facts

Status: accepted 2026-09-18. Implementation pending at decision time; current status is recorded in docs/decision-log.md.

Context: an atom is stored twice from one payload, as a structured target and as generated predicate source (`gates/verifier_suite.py:760-762`), and two readers score it: the Verdict reads the predicate source (`runner/verdict.py`), while `check_run` over the target is "Used by the D79 checks below, never by the Runner" (`:797-799`), with the hole named in the `_predicate` docstring (`:722-730`). Three further places in the reward read text rather than state: `communicated()` is substring containment over every assistant message (`runner/atom_context.py:154-155`), `user_confirmed_before` matches ten English affirmation words as substrings (`gates/verifier_suite.py:56`, `atom_context.py:160-166`), and judge atoms enter the pass evaluation (`runner/verdict.py:121-140`).

Decision: the structured atom target becomes the only meaning of an atom, and one interpreter in the Runner layer is called by both the Verdict and the gates (the D79 suite, probes, the trusted ruling, loosening, false rejection). Generated predicate source stops carrying meaning of its own, except for Hard rules, which are compiled policy source by nature. Anything in the reward that concerns text is grounded in facts instead: a communicate atom passes only when the value the Candidate states matches a value a tool returned to it in that Run, a confirm atom is settled by the Simulated user's own typed record that it agreed before the write, and a model judge leaves the pass condition entirely, its opinion reported beside the Verdict and never deciding it. The reward is computed by code alone. The change lands on a re-freeze of its own, and the first step is a differential count: score every stored Run in the three workdirs with both scorers, no model calls, and list every disagreement by Task id and atom kind.

Why: there should be only one source of truth. Two meanings for one atom is two rewards, and which one a Task was graded by depends on which reader ran. The text-reading checks are the same fault in a different place: a substring found anywhere in any assistant message, or one of ten English words, is a reward a Candidate reaches by producing the right shape of sentence rather than by doing the work, and it does not survive a corpus that speaks differently.

Considered: keeping both scorers and gating their agreement, refused because a disagreement rate is a number about the harness rather than a fix, and the reward would still depend on which reader ran; making the generated predicate source the single meaning, refused because it is model-written text that no gate can read structurally, while the target is data; and keeping the judge inside the pass condition with its disagreement reported, refused under the standing rule that a judge never awards a pass (D110, ADR-0007).

Consequences: no-write Tasks (D156) keep their only signal but get stricter, and Hard rules that only a judge can check leave trusted until they are compiled to code, so trusted may fall before it rises. The confirm half depends on the Simulated user recording agreement as a typed event (D256). The historical differential count is recorded under D254 in docs/decision-log.md; it does not establish that the implementation is complete. See decision log D254 and D255.
