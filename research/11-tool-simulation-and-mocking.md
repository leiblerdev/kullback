# Simulating and mocking agent tools for cross-model re-runs

Research sweep, 2026-08-26. Source: web research agent. Topic 11. (Search budget exhausted; sources via direct fetch.)

## A. LLM-simulated tools

- **ToolBench instability.** Only 44.4% of ToolBench API calls still succeed; 49.2% unavailable ([arXiv 2403.07714](https://arxiv.org/html/2403.07714)). Real tools drift; any "replay later" design must assume it.
- **StableToolBench: cache, then real, then GPT-simulate.** Virtual API server tries cache, live API, then a GPT-4 simulator with up to five cached real calls as few-shot. 90% of simulated responses judged reasonable. **Cache hit rate 97.0% for the in-domain model but 77.8% for an out-of-domain newer model**, because a new model makes calls the original never made. That 20-point drop is the miss problem.
- **MirrorAPI: the best fidelity study.** Simulators trained on 95,872 request-response pairs from 7,500 APIs. OOD successful calls: BLEU-4 35.6 (MirrorAPI SFT) vs 13.4 (GPT-4o) vs 19.2 (o1-preview). Agent performance in the MirrorAPI-simulated environment tracked the real environment; GPT-4o-simulated environments showed "significantly lower performance" ([arXiv 2503.20527](https://arxiv.org/html/2503.20527)). Takeaway: an untrained frontier LLM prompted from a schema is a poor simulator; a model trained on logged pairs is usable.
- **ToolEmu.** Emulated trajectories free of critical issues 91.9% (standard), 85.6% (adversarial); identified-failure precision 72.5% / 68.8%; setup under 15 minutes vs 8 hours for real sandboxes ([arXiv 2309.15817](https://arxiv.org/abs/2309.15817)). Roughly one in ten emulated trajectories contains a fidelity-breaking error.
- **Simia (Nov 2025).** No agreement metric vs real feedback; state lives only in the context window; authors admit "distributional bias" ([arXiv 2511.01824](https://arxiv.org/html/2511.01824)).
- Others: Kimi K2 tool simulator with state and controlled failures ([arXiv 2507.20534](https://arxiv.org/html/2507.20534)); SynthAgent keeps a per-task finite mapping of prior calls to responses so identical calls get identical answers ([arXiv 2601.22511](https://arxiv.org/html/2601.22511)); Gecko validates schema-conforming, state-consistent responses ([arXiv 2602.19218](https://arxiv.org/abs/2602.19218)); ARTIS: "naive LLM-based simulators struggle to capture rare but high-impact failure modes" ([arXiv 2602.01709](https://arxiv.org/abs/2602.01709)).
- **Counter-position: code-backed state beats LLM simulation.** EnvFactory ([arXiv 2605.18703](https://arxiv.org/abs/2605.18703)), EnvScaler ([arXiv 2601.05808](https://arxiv.org/abs/2601.05808)), Agent World Model (ICML 2026: 1,000 code environments "backed by databases, providing more reliable and consistent state transitions") ([arXiv 2602.10090](https://arxiv.org/abs/2602.10090)), SynthTools filters tools that cannot be reliably emulated ([arXiv 2511.09572](https://arxiv.org/abs/2511.09572)), ComplexMCP seed-driven deterministic failures ([arXiv 2605.10787](https://arxiv.org/abs/2605.10787)).
- **MCP tool simulation in products.** Microcks 1.12/1.13 exposes OpenAPI/GraphQL/gRPC mocks as MCP endpoints with a stateful store ([release](https://microcks.io/blog/microcks-1.13.0-release/)); Specmatic MCP server ([GitHub](https://github.com/specmatic/specmatic-mcp-server)).

## B. Recorded-response replay and cassettes

- **Baseline**: vcrpy match on subsets of method/uri/body/headers ([docs](https://vcrpy.readthedocs.io/en/latest/configuration.html)); pytest-recording default `none` (unrecorded request fails) ([GitHub](https://github.com/kiwicom/pytest-recording)).
- **Agent-specific (2026)**: `agent-vcr` (PyPI): MCP JSON-RPC proxy, strategies `exact`, `method`, `method_and_params` (default), `subset`, `sequential`, error injection ([PyPI](https://pypi.org/pypi/agent-vcr/json)). `ai-agent-vcr`: git-branch rollback and a `GoldenRunCache` keyed by model, prompt hash, code commit, tool-schema hash ([GitHub](https://github.com/ixchio/agent-vcr)). `mcp-recorder`: record via proxy, replay as mock, `verify` diffs an updated server ([GitHub](https://github.com/devhelmhq/mcp-recorder)). `claude-agent-cassette`: fail-closed `CassetteMismatchError` ([PyPI](https://pypi.org/pypi/claude-agent-cassette/json)). `langchain-replay`: records LLM decisions, re-executes tools; timestamps/UUIDs replay verbatim ([PyPI](https://pypi.org/project/langchain-replay/)). `langgraph-cassette`: `CASSETTE_REPLAY_MISS=mock|live` ([GitHub](https://github.com/arijit1/langgraph-cassette)). LangGraph time travel re-fires LLM calls; not a cassette ([docs](https://docs.langchain.com/oss/python/langgraph/use-time-travel)).
- **Miss handling from the HTTP world**: Hoverfly `spy` (forward unmatched to live) and `synthesize` ([docs](https://docs.hoverfly.io/en/latest/pages/keyconcepts/modes/modes.html)); WireMock `repeatsAsScenarios` turns repeated identical requests into an ordered scenario ([docs](https://wiremock.org/docs/record-playback/)); Microcks `FALLBACK` / `PROXY_FALLBACK` ([docs](https://microcks.io/documentation/explanations/dispatching/)); Keploy eBPF record/replay with fuzzy matching ([docs](https://keploy.io/docs/keploy-explained/how-keploy-works/)).

## C. Schema-driven and stateful mock servers; resettable state

- **Stateless**: Prism static examples or Faker data; persistence only a roadmap item ([README](https://raw.githubusercontent.com/stoplightio/prism/master/README.md)).
- **Stateful**: WireMock scenarios and Cloud dynamic state ([docs](https://docs.wiremock.io/dynamic-state/overview)); Mockoon CRUD routes over data buckets (restart = reset) ([docs](https://mockoon.com/docs/latest/api-endpoints/crud-routes/)); `@msw/data` in-memory relational store ([README](https://raw.githubusercontent.com/mswjs/data/main/README.md)); Microcks JS dispatchers with `store` ([docs](https://microcks.io/documentation/explanations/dispatching/)); Prisma shadow database as disposable twin ([docs](https://www.prisma.io/docs/orm/prisma-migrate/understanding-prisma-migrate/shadow-database)).
- **DB branching/snapshots**: Neon copy-on-write branches, reset-from-parent, Snapshots API for agents ([docs](https://neon.com/docs/introduction/branching)); Postgres `CREATE DATABASE ... TEMPLATE` ([docs](https://www.postgresql.org/docs/current/manage-ag-templatedbs.html)); Database Lab Engine thin clones (10 TiB in under 2 s) ([postgres.ai](https://postgres.ai/docs/database-lab)); SQLite `VACUUM INTO` ([sqlite](https://sqlite.org/lang_vacuum.html)); Dolt branches; lakeFS.
- **Sandbox snapshot/fork**: E2B pause (~4 s/GiB) and snapshots; templates cold-start faster ([docs](https://docs.e2b.dev/sandbox/snapshots)); Modal FS and memory snapshots ([docs](https://modal.com/docs/guide/sandbox-snapshots)); Daytona cold/hot snapshots and fork ([docs](https://www.daytona.io/docs/en/snapshots/)); Vercel Sandbox Firecracker `Sandbox.fork` ([docs](https://vercel.com/docs/sandbox/concepts/snapshots)); Firecracker: "guest network connectivity is not guaranteed to be preserved", restored snapshots duplicate random seeds ([docs](https://github.com/firecracker-microvm/firecracker/blob/main/docs/snapshotting/snapshot-support.md)).

## D. Inferring tool behaviour from traces

- **Declared hints.** MCP `ToolAnnotations`: `readOnlyHint` (default false), `destructiveHint` (default true), `idempotentHint` (default false), `openWorldHint` (default true); clients "MUST consider tool annotations to be untrusted unless they come from trusted servers" ([spec](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)). Spec 2026-07-28 adds "Stateful Tools" guidance: state carried by explicit handles ([spec](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)). RFC 9110 safe/idempotent methods; Stripe `Idempotency-Key` semantics.
- **Learning I/O models from logged pairs**: few-shot from cache (StableToolBench), per-task finite mapping (SynthAgent), SFT on tens of thousands of pairs (MirrorAPI; 2.5x response similarity over prompting). Traffic recorders: WireMock recorder, Keploy, proxymock (HTTP, Postgres, gRPC full-fidelity) ([docs](https://docs.speedscale.com/proxymock/)).
- **Inferring state transitions**: a value in one tool's output that later appears in another tool's arguments marks a state dependency. No paper classifies tools as read-only/idempotent/destructive purely from traces; heuristics below are synthesis, not published results.

## Recommended per-tool strategy table

| Tool class (from traces) | Default strategy | Miss policy | Fidelity risks |
|---|---|---|---|
| Pure/deterministic (same args always same result) | Cassette, `method_and_params` | Execute for real, append to cassette | Near zero; schema drift caught by `verify` |
| Read-only, closed world (DB/file reads on state we own) | Snapshot the state, execute for real | n/a | State must be restored at the trace's point in time |
| Read-only, open world (web search, third-party GET) | Cassette first; miss to trained simulator seeded with cassette pairs | Real if cheap and non-billable, else simulate and flag | Untrained LLM simulation poor (BLEU 13.4); time drift; expect 20%+ misses with a new model |
| Write, closed world (our DB, files, sandbox) | Branch/snapshot and execute for real | n/a | Snapshot must include every stateful dependency |
| Write, open world, idempotent (PUT, upsert, Idempotency-Key POST) | Stateful mock seeded from traces (Mockoon CRUD, @msw/data, WireMock, Microcks store) | Simulate with state ledger | Mock only knows fields seen in traces; real validation rules missing |
| Write, open world, destructive (send email, charge card, delete remote) | Simulate, never execute | Simulate, log for human review | ToolEmu-scale 8-14% critical-issue rates; rare failures under-represented |
| Time/random/session tokens | Freeze (inject recorded clock/seed) | n/a | Replayed timestamps/UUIDs leak |

**Decision procedure per tool.**
1. Profile: call count; distinct arg sets; response entropy for repeated identical args (identical implies pure); `isError` presence; outputs appearing verbatim in other tools' arguments (handle flow); read-after-write pairs where a later read changed after an earlier write with overlapping identifiers (mutation evidence); declared annotations and HTTP method; name lexicon (get/list/search vs create/update/delete/send/pay).
2. Trust annotations only from servers you control; otherwise a hypothesis to test. Absence of evidence is not read-only: default any unprofiled tool to "write, open world, destructive".
3. Map to a table row. Split closed from open by whether the state behind the tool can be snapshotted; if it can, snapshot and run for real.
4. Wire miss handling per row and record the cassette hit rate per re-run. A cross-model run with under ~80% hits is mostly a simulation run and should be scored as such.
5. Before trusting simulated rows: hold out 10% of cached pairs and measure simulator agreement (BLEU-4 plus LLM judge), sample 50 trajectories for a ToolEmu-style critical-issue check (target >90% clean), compare pass rates real vs simulated on a task subset. Retrain the simulator on the customer's own traces rather than prompting from schema.
